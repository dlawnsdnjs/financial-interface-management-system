# 보험사 금융 IT 인터페이스 통합관리시스템 (FIMS) 요구사항 정의서

## 1. 프로젝트 개요
- **명칭**: FIMS (Financial Interface Management System)
- **목적**: 보험사의 복잡한 내/외부 인터페이스를 단일 화면에서 통합 관리함으로써 운영 효율성을 극대화하고, 장애 발생 시 신속한 대응 체계를 구축함.

## 2. 주요 대상 프로토콜
- **REST API**: 대고객 서비스 및 내부 마이크로서비스 간 연동 (JSON).
- **SOAP**: 대외 기관(금감원, 유관기관)과의 레거시 연동 (XML).
- **MQ (Message Queue)**: 비동기 데이터 교환 및 트랜잭션 보장 연동.
- **Batch**: 일 단위, 월 단위 대용량 데이터 주기적 처리.
- **SFTP/FTP**: 대용량 파일(정산 데이터, 고객 정보 등) 기반 연동.

## 3. 기능적 요구사항 (Functional Requirements)

### 3.1 인터페이스 등록 및 설정
- **기능**: 인터페이스 ID, 명칭, 프로토콜 타입, URL/엔드포인트, 인증 정보(API Key, OAuth)를 등록/수정/삭제.
- **매핑**: 데이터 레이아웃(JSON/XML) 정의 및 시스템 간 필드 매핑 설정.

### 3.2 통합 대시보드 및 실시간 모니터링
- **실시간 현황**: 현재 활성화된 인터페이스 수, 실시간 TPS, 성공/실패율 시각화.
- **장애 감지**: 비정상적인 응답 시간이나 연속 실패 발생 시 대시보드에 즉각 표시.

### 3.3 실행 및 제어
- **수동 실행**: 테스트 또는 긴급 처리를 위한 특정 인터페이스 즉시 실행.
- **스케줄링**: Batch 작업을 위한 크론(Cron) 표현식 기반 스케줄 제어.

### 3.4 장애 복구 및 재처리 (Retry)
- **개별 재처리**: 실패한 개별 트랜잭션의 페이로드를 확인하고 즉시 재시도.
- **일괄 재처리**: 특정 시간대 또는 특정 에러 코드 기반의 실패 건 일괄 재처리.

### 3.5 로그 및 사후 분석
- **전문 로깅**: 모든 요청(Request)과 응답(Response) 데이터 로깅 (민감 정보 마스킹 필수).
- **성능 분석**: 인터페이스별 평균 응답 시간, 최대 부하 시간대 등 통계 데이터 제공.

## 4. 비기능적 요구사항 (Non-functional Requirements)

### 4.1 보안 (Security)
- **데이터 마스킹**: 주민등록번호, 계좌번호, 카드번호 등 개인정보는 로그 및 화면에서 '*' 처리.
- **접근 제어**: 역할 기반(Admin/Operator)의 권한 분리 및 관리자 로그인 인증 필수.

### 4.2 안정성 및 성능 (Reliability & Performance)
- **트랜잭션 무결성**: 연동 실패 시 데이터 일관성을 유지할 수 있는 체크포인트 로직 구현.
- **확장성**: 향후 신규 프로토콜 추가가 용이한 플러그인 아키텍처 지향.

## 5. 유스케이스 (Use Cases)
- **UC-01**: 관리자가 새로운 대외기관 연동 API를 등록한다.
- **UC-02**: 운영자가 대시보드에서 '실패'로 뜬 인터페이스를 확인하고 재처리 버튼을 클릭한다.
- **UC-03**: 정산 배치 작업이 밤 12시에 SFTP를 통해 정상적으로 수행되었는지 확인한다.
